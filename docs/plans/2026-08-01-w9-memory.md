# W9 Long-Term Memory & 100-Turn Soak Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Preserve key facts/relationships/unsolved events across 50–100 turns WITHOUT sending full raw history, using a deterministic rule-based memory selector (ADR-006: NO vector DB). ST-029 (MemoryEntry event creation), ST-030 (summary contract + source-coverage), ST-031 (rule-based MemorySelector), ST-032 (100-turn synthetic soak harness).

**Architecture:** All in `story-core` (no UI/HTTP/FS — ADR-003). `MemoryEntry`/`MemoryFact` already exist (story-model W2). The `MemorySelector` assembles prompt memory from tiers (fixed/state/recent/summary/event) using a scoring formula + absolute-include rules under a token budget, deterministically. Event firing (W3 reducer) already records `fired_events`; W9 derives `MemoryEntry`s from those deterministically. The 100-turn soak is a Mock-driven harness test asserting invariants + budget.

**Tech Stack:** story-core (+ sha2). ADR-006: rule-based only; vector search is a future ADR, never a substitute for canonical state.

## Part A — memory creation from events (new `memory.rs` in story-core)

```rust
pub fn memories_from_turn(result: &ApplyResult, pack: &StoryPack, turn: u32) -> Vec<MemoryEntry>;
```
- For each `fired_events` id whose `EventDef` maps to a memory-worthy kind (confession/promise/secret-reveal/relationship-change/key-item/first-meeting/betrayal — use a `memory_kind` hint on `EventDef` or derive from the event id prefix/kind), build a `MemoryEntry`:
  - `kind`: derived from the event.
  - `facts`: `MemoryFact { subject, predicate, object, known_by, certainty }` — derived deterministically from the event effects + trigger (e.g. a promise event → fact "약속" with participants as known_by).
  - `participants`: characters in the event's deltas/effects.
  - `location`: `result.state.location`.
  - `importance`: from the event kind (promise/secret high; key-item medium).
  - `unresolved`: true for promises/secrets until a resolving event fires (deterministic: an event with id matching a "resolves" relation clears it — for MVP, a simple convention or a flag).
  - `source_history_ids`: the turn's history entry id (so summaries can't add facts without a source).
  - `created_turn`: turn.
- Deterministic: same `ApplyResult` + pack ⇒ identical `Vec<MemoryEntry>`.
- The engine appends these to `state.memories` on accept (extend `reduce_accept`).

Tests (ST-029): a promise event, a secret-reveal, a relationship-change each produce the expected `MemoryEntry`; participants/known_by correct; determinism; a resolving event clears `unresolved`. Fixtures: 약속/비밀/호칭변화/관계원인 preserved; knowledge-owner (known_by) not violated.

## Part B — summary source-coverage validation (new `summary.rs` in story-core)

```rust
pub fn validate_summary(summary: &TurnSummary, sources: &[&HistoryEntry]) -> Result<(), CoreError>;
```
- Required fields (per §12.3): facts, interpretation, unresolved, knowledge_changes, address_form_changes, important_player_actions, source_history_ids.
- **Source-coverage check:** every fact/relationship-change/knowledge-change in the summary MUST trace to a `source_history_id` present in `sources`. If the summary asserts a fact with no source ⇒ `Err` (reject — do not commit). (This is the "summary may not invent facts" rule.)
- Missing required field ⇒ `Err`.
Tests (ST-030): a summary with an unsourced fact is rejected; a faithful summary passes; a missing-field summary is rejected; address-form-change cause preserved.

## Part C — rule-based MemorySelector (new `memory_selector.rs` in story-core)

```rust
pub struct SelectionTrace { pub included: Vec<MemoryEntry>, pub excluded_reason: Vec<(MemoryEntry, String)>, pub tokens_by_tier: BTreeMap<&'static str, usize>, pub total_tokens: usize, pub budget_tokens: usize }
pub fn select(state: &GameState, pack: &StoryPack, recent: &[HistoryEntry], ctx: &SelectionContext) -> SelectionTrace;
pub struct SelectionContext {
    pub current_participants: BTreeSet<CharacterId>,
    pub current_location: LocationId,
    pub active_route: Option<String>,
    pub mentioned_proper_nouns: BTreeSet<String>,   // from the current scene / pending action
    pub budget_tokens: u32,
}
```
Tiers assembled in priority order:
1. **Fixed memory** (pack world/style + immutable char config + current route premise) — always included up to its tier budget.
2. **State memory** (canonical compact JSON of current state) — always included.
3. **Recent memory** (last N turns raw text, current-scene-first).
4. **Event/summary memory** — scored & selected.

Scoring formula (verbatim, weights from Technical Spec §12.2):
```
score = importance*4 + unresolved*8 + participant_match*5 + location_match*3 + route_match*6 + explicit_reference*10 + recency_bucket - already_recalled_recently*3
```
(`participant_match`/`location_match`/`route_match`/`explicit_reference` are 0/1; `recency_bucket` from `created_turn`; `already_recalled_recently` from `last_recalled_turn`.)

**Absolute-include rules (override score, always included until budget):** current route premise, in-progress (unresolved) promises, cause of relationship-stage change, current participant honorific rules, proper nouns mentioned this scene, unresolved key events.

**Token budget:** a simple deterministic estimator `estimate_tokens(s)` (documented heuristic — e.g. `max(char_count, display_width/2)` clamped; Korean-aware via unicode-width). Enforce `fixed + state + memory + recent + response_reserve ≤ context_budget_tokens` (from ProviderConfig). Drop lowest-score non-absolute items first when over budget; never drop an absolute-include item (if absolute-includes alone exceed budget, that's a diagnosed overflow, not a silent drop — record in trace).

`select` updates `last_recalled_turn` on included entries (caller applies).

Tests (ST-031): absolute-include always present; scoring orders entries correctly; budget drops lowest-score non-absolute first; overflow diagnosed not silent; **deterministic** (identical state ⇒ identical selection); current-route premise + unresolved promise included; selection trace populated.

## Part D — 100-turn synthetic soak harness (new `tests/soak.rs` or `tests/soak/`)

A Mock-driven deterministic 100-turn run:
- Load rainy-reunion, init engine, drive 100 turns with a deterministic Mock (scripted legal drafts cycling legal patches). After each turn: run `MemorySelector::select`, accumulate memories, autosave-style snapshot via `snapshot_payload` + `SaveStore` to a tempdir, reload once mid-way.
- Assertions: state invariants hold every turn (revision == turn, no negative inventory, stats in range), memory set grows but stays bounded, prompt memory selection stays within budget every turn, save round-trip at turn 50 + 100 identical, **0 losses of unresolved events/relationship-causes/knowledge-owners** in the release fixture, core-event recall ≥ 90% (the selector includes the fired key events).
- Report a budget summary (tokens by tier at turn 100). Separate 20/50/100 reports if convenient.
- This is a normal (non-ignored) test — Mock only, no network.

Tests (ST-032): the soak completes 100 turns with all invariants; a mid-run save/reload preserves state; budget never silently exceeded.
