# 홈 메뉴 "새 게임" 확인 가드 — 마지막 무확인 리셋 입구

2026-10-22 · 요청: "사용자가 잘 판단하지 않더라도 잘 동작" (같은 날 세 번째
소규모 사이클 — 2026-10-22-retry-and-newgame-guard.md의 잔여 입구 제거.)

## 연구와 근거

두 번째 사이클에서 게임 중 `n`/ㅜ에 확인 모달을 두었다. 그러나 리뷰 과정에서
동일한 파괴 경로가 홈 메뉴에 그대로 남는다: 홈 메뉴의 **첫 행이 "새 게임"이고
기본 선택**이어서, 팩 선택·가져오기를 하려고 홈을 열고 Enter를 잘못 누르면
진행 전체가 즉시 리셋된다(`choose_home(0)` → `HomeRequest::StartNew`, 확인
없음). 홈 메뉴 `n`/ㅜ와 메뉴 행 클릭도 같은 함수로 수렴한다. 첫 사이클에서
StartNewGame은 되돌리기 링까지 비우므로(2026-10-22-turn-undo.md) 우발 리셋은
복구 불가다. 시작 메뉴 경로는 직전 계획에서 "명시적 선택"으로 제외했지만,
기본 선택이 파괴 행위라는 점은 판단 미스 그 자체다 — 같은 가드로 닫는다.

## 목표와 범위

- **달라지는 결과**: 진행이 있을 때(턴 > 0) 홈 메뉴의 "새 게임"(Enter·클릭·
  `n`/ㅜ)은 확인 모달을 먼저 보여준다. Enter → 홈 경로의 기존 새 게임 흐름
  (greeting 리스캔 포함)으로 진행, Esc → 모달만 닫히고 홈 메뉴가 유지된다.
  턴 0(잃을 것이 없음)은 종전대로 즉시 시작.
- **제외**: 게임 중 `n` 키 경로(이미 모달 있음 — 발행 방식 유지), 로딩 중
  동작(게이트가 이미 차단).

## 설계 메모

- 모든 홈 새 게임 진입(메뉴 Enter·클릭·`n`/ㅜ)이 `choose_home(0)`으로 수렴하므로
  가드는 한 지점. 모달의 키 선점(handle_key 순서)과 마우스 차단(handle_mouse
  초입 가드)은 직전 사이클 구현을 그대로 재사용 — 신규 렌더/입력 코드 없음.
- 출처 플래그: 게임 중 `n`은 기존대로 `EngineCommand::StartNewGame`을 반환하고,
  홈 출처는 `home_request = StartNew`로 호스트의 greeting 리스캔 흐름을 유지한다.

### 검증 중 수정 이력

- 1차 실행에서 기존 홈 테스트 4종이 실패 — 원인은 테스트가 `sample_view(0)`(선택지 0)를
  쓰면서도 `turn=1` 상태로 홈 즉시 시작을 기대한 것. 의도에 맞게 `turn=0`을 명시해
  갱신(가드는 진행이 있을 때만 발화하는 것이 올바른 동작). 제 신규 테스트도
  시나리오 오류(홈이 닫힌 뒤 Enter를 다시 누름)를 바로잡았다.
