# 사용성 단순화 — 키맵 그룹핑·한영 병기 제거·라벨 축약

2026-10-22 · 요청: "사용성이 너무 복잡한 것 같아. 확인하고 개선해줘."
(review-design 구현 모드 감사 → 개선 사이클. 기능 삭제는 없다 — 표현·구조만.)

## 감사 결과 (구현 모드 관찰, 2026-10-22)

1. **키맵 24행이 평면 나열** — 게임 키 20종에 설정 화면 전용 키(e/i/g/f)까지
   섞여 있고 그룹이 없다. 도움말(`?`)이 유일한 학습 경로인데…
2. **도움말 팝업이 넘친다** — 24행을 높이 20짜리 팝업에 2열(각 12행)로
   강제 배치. 긴 행(예: "표정 스프라이트 켜기/끄기 (설정 화면)")이
   줄바꿈되면 열 아래 행이 팝업 밖으로 밀려 **보이지 않는다** — 도움말이
   도움이 되지 않는 구조적 결함.
3. **모든 행에 한영 병기 노이즈** — 각 키가 2벌식 별칭까지 표에 반영돼
  (`u/ㅕ` 표기는 문서용이고 표 자체는 Latin) 행마다 설명이 길다.
4. **푸터 라벨 과장** — wide 폭에서 10개 세그먼트, 최长 "선택지 다시
   만들기". 같은 키가 로딩 중에도 동일한 "다시 만들기"임을 라벨이
   가르치지 못한다.

## 목표와 범위

- **달라지는 결과**:
  1. 키맵을 **"게임 화면" / "설정 화면" 두 그룹**으로 나누고 그룹 헤더를
     둔다. 설정 전용 키(e/i/g/f)는 "설정 화면에서" 그룹으로 이동해 맥락이
     명확해진다.
  2. 각 행의 설명을 축약하고, 한글 자판 안내는 표 전체에 한 줄
     ("한글 2벌식도 같은 물리 키 (q=ㅂ, j=ㅓ, s=ㄴ …)")로 대체한다.
  3. 도움말 팝업이 그룹핑·축약된 내용을 **잘림 없이** 수용한다(높이 재조정).
  4. 푸터 라벨 축약: "선택지 다시 만들기" → "다시 만들기" (로딩 중 같은
     키와 의미를 통일해 가르친다).
- **제외**: 기능·키 바인딩의 삭제나 변경(모든 키 유지), 모달/확인 절차 변경
  (직전 사이클들의 안전 장치 유지), 설정 화면 레이아웃 재설계.

## 설계 메모

- **그룹 모델**: `KeymapRow`에 `group: KeymapGroup`(Game/Settings) 필드를
  추가하고 `keymap_lines`는 헤더 행을 삽입해 단일 목록(설정 화면 블록·도움말
  공용), `keymap_lines_two_columns`는 헤더를 포함해 균형 분할한다. 기존
  `KEYMAP` 소비자(settings 스냅샷, help)는 행 수가 늘어도 렌더만 바뀐다.
- **한글 별칭**: 코드의 바인딩(2벌식 매칭)은 그대로 두고 표시만 단순화 —
  "한글 2벌식도 같은 물리 키" 안내 1줄이 대신한다. 기존 컨벤션
  (`u/ㅕ` 표기)은 docs/UI-NAVIGATION.md가 계속 담당한다.
- **잘림 검증**: 팝업 본문(높이 20−2경계=18행 × 2열=36행 예산)에 그룹
  헤더 2 + 게임 17 + 설정 4 + 안내 1 ≈ 24행 + 줄바꿈 여유 — 축약된 행은
  1줄 이내로 맞춰 여유를 확보한다. 렌더 스냅샷으로 80×24 관찰.
