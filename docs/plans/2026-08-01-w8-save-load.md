# W8 Save/Load & Persistence Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Durable, corruption-resistant saves: `SaveEnvelope` (version + checksum + payload), atomic writes (same-dir temp → flush/sync → rename → `.bak`), load with checksum/migration/diagnosis, and a 3-slot + autosave store. ST-025 (envelope/checksum/round-trip), ST-026 (atomic write + backup), ST-027 (migration + corruption recovery), ST-028 (slot UI). **The MVP quality-gate *metrics* (95%/98% etc.) require a real model and remain a runtime gate — NOT closed by this code.**

**Architecture:** `story-persistence` already has the `SaveEnvelope`/`SavePayload` types in `story-model` (W2) and depends on sha2/tempfile/semver/serde_json. Implement `json_store` (read/write slots), `atomic_write` (9-step), `checksum` (SHA-256), `migration` (v0→v1; reject future major). The engine emits a `PersistStableState` effect (already in the `EngineEffect` set if present; if not, add it as a described effect — the app executes it). Save/Load slot UI is a thin TUI screen; the gate is the round-trip + fault-injection tests, not the UI polish.

**Tech Stack:** sha2 0.11.0, tempfile 3.27.0, semver, serde_json, thiserror. ADR-004: JSON store; revisit to SQLite only when a 100-turn save exceeds 10MB.

## The save contract (from Technical Spec §13, W2 types already exist)
`SaveEnvelope { save_schema_version, engine_version, story_id, story_version, pack_schema_version, slot_id, description, saved_at, chapter_label, scene_label, checksum_algorithm: "sha256", payload_checksum: String, payload: SavePayload }`
`SavePayload { stable_state: GameState, memories: Vec<MemoryEntry>, history: Vec<HistoryEntry>, audit_tail: Vec<StateChangeLog> }`
- **Forbidden in saves:** full prompts, provider API key, incomplete Writer buffer, default logs (none of these are in GameState anyway — verify no leak).
- `checksum_algorithm = "sha256"`; `payload_checksum` = hex SHA-256 of the canonical serialized `payload` (serde_json `to_vec` — deterministic via BTreeMap ordering).

## Part A — story-persistence: atomic write + checksum (new `atomic_write.rs`, `checksum.rs`)

`checksum.rs`:
```rust
pub fn payload_checksum(payload: &SavePayload) -> String;   // hex sha256 of serde_json::to_vec(payload)
pub fn verify(payload: &SavePayload, checksum: &str) -> bool;
```

`atomic_write.rs` — the 9-step procedure (Technical Spec §13.2):
```rust
pub fn atomic_write_json(path: &Path, bytes: &[u8], bak_generations: usize) -> std::io::Result<()>;
```
1. Create a unique temp file in the SAME directory as `path` (e.g. `.<name>.tmp.<rand>`).
2. Write `bytes`, flush, `sync_all` (fsync the file).
3. If `path` exists, rotate: keep up to `bak_generations` `.bak` files (e.g. move existing → `.bak`, age older `.bak.N`).
4. Atomic rename temp → `path`.
5. `sync_dir` (fsync the parent directory) where the platform allows (on macOS/Linux use `std::fs::File::open(parent)?.sync_all()`; best-effort, ignore errors that are unsupported).
6. Return Ok. (Reopen+verify happens at load / a higher level.)
On ANY error: leave the existing `path` untouched, clean up the temp file.

## Part B — story-persistence: store + migration + load (new `json_store.rs`, `migration.rs`, extend `error.rs`)

`json_store.rs`:
```rust
pub struct SaveStore { root: PathBuf, bak_generations: usize }   // root = saves dir
impl SaveStore {
    pub fn open(root: &Path) -> std::io::Result<Self>;
    pub fn slot_path(&self, slot_id: &str) -> PathBuf;
    pub fn list_slots(&self) -> Vec<SlotMeta>;                    // read each envelope header (no full payload) for the slot screen
    pub fn save(&self, envelope: SaveEnvelope) -> std::io::Result<()>;   // serialize → checksum already inside → atomic_write
    pub fn load(&self, slot_id: &str) -> Result<SaveEnvelope, SaveError>;
    pub fn delete(&self, slot_id: &str) -> std::io::Result<()>;
}
pub struct SlotMeta { slot_id, story_id, saved_at, chapter_label, scene_label, description }
```
`save`: serialize payload → compute checksum (if not set) → build envelope → `serde_json::to_vec_pretty(&envelope)` → `atomic_write_json(slot_path, .., bak_generations)`. **Do NOT expose the slot in `list_slots` until the write fully succeeds** (Acceptance §13).

`load` order (Technical Spec §13.3):
1. Read file bytes.
2. Parse envelope JSON (syntax error → `SaveError::TruncatedOrCorrupt`).
3. Verify `payload_checksum` against `payload` (mismatch → `SaveError::ChecksumMismatch` — do NOT mutate anything).
4. Check `save_schema_version`: if greater than current → `SaveError::UnsupportedVersion` (show update guidance); if older → migrate via `migration::migrate_payload`.
5. Domain invariants (non-empty story_id, revision sane, etc.) → else `SaveError::InvalidPayload`.
6. Return the envelope (caller restores to a TEMP state then swaps on confirmation — for the slice, load returns the envelope; the app/engine decides to swap).

`migration.rs`:
```rust
pub fn migrate_payload(payload: SavePayload, from: u32, to: u32) -> Result<SavePayload, SaveError>;
```
v0→v1: fill any missing default fields (e.g. `stable_state.save_schema_version = 1`, default empty memories if absent). Cross-major (from > to) → `UnsupportedVersion`. **Never mutate the on-disk file** — migration is in-memory only; the original save is preserved.

`SaveError` (extend `error.rs`):
```rust
pub enum SaveError {
    Io(io::Error), MissingSlot, TruncatedOrCorrupt(String), ChecksumMismatch { slot: String },
    UnsupportedVersion { found: u32, supported: u32 }, InvalidPayload(String), Serde(serde_json::Error),
}
```
Korean user-facing messages where surfaced (the engine/app maps to `DomainErrorView`).

## Part C — engine effect + thin Save/Load slot screen
- `story-core` `EngineEffect`: add `PersistStableState { slot_id: String, description: Option<String> }` (a described effect; the app executes it by calling `SaveStore::save`). The engine builds the `SavePayload` from `EngineState` (game + memories + history + audit_tail) — add a helper `EngineState::snapshot_payload() -> SavePayload`. Emit `PersistStableState` after each accepted turn (autosave to the "autosave" slot) — make autosave-on-accept configurable (default on for MVP).
- `story-tui`: a minimal `SaveLoad` screen (slot list from `SlotMeta`, overwrite/delete confirmations, load). Snapshot test. Keep UI light — the gate is the persistence round-trip, not UI polish.

## Part D — tests (the gate)
- **100-iteration round-trip:** save → load → assert identical payload (checksum + domain equality) 100×.
- **Atomic fault injection:** inject failures at each stage (temp write fail, rename fail) and confirm the PRE-EXISTING save is byte-identical and still loadable. (Use a wrapper that can fail at a chosen step, or `tempfile` + controlled perms.)
- **`.bak` rotation:** saving twice keeps a `.bak`; saving beyond `bak_generations` ages out the oldest.
- **Checksum mismatch:** tamper one byte in the saved JSON → load returns `ChecksumMismatch`, current game unchanged.
- **Truncated JSON:** truncate the file → `TruncatedOrCorrupt`.
- **Migration:** a v0 fixture loads and is migrated to v1 in-memory; the original file is unchanged.
- **Unsupported future version:** a `save_schema_version=99` envelope → `UnsupportedVersion`.
- **Slot isolation:** a failed/partial save does NOT appear in `list_slots`.
- **No secret leak:** assert the serialized envelope contains no prompt/api-key/secret markers (plant none, but assert the round-trip payload has no such fields).
