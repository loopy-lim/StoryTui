# StoryTUI 제품 요구사항 문서(PRD)

문서 버전: 1.0-draft  
작성 기준일: 2026-07-31  
대상 플랫폼: Apple Silicon M1 Max, 통합 메모리 64GB, macOS  
제품 형태: 완전 로컬 한국어 생성형 인터랙티브 소설 엔진 및 Rust TUI 클라이언트

## 1. 문서 목적

이 문서는 StoryTUI가 해결할 문제, 목표 사용자 경험, MVP와 v1.0 범위, 기능·비기능 요구사항, 성공 지표와 출시 기준을 고정한다. 구체적인 타입, API, 오류 복구, 저장 형식은 `StoryTUI_Technical_Spec_KO.md`가 정의하고, 개발 순서는 `StoryTUI_Implementation_Plan_KO.md`가 정의한다.

## 2. 문제 정의

현재의 로컬 LLM 채팅 도구는 긴 한국어 인터랙티브 소설에 필요한 게임 규칙, 상태, 기억, 분기와 저장을 대부분 대화 문맥에 맡긴다. 그 결과 다음 문제가 발생한다.

- 20~100턴이 지나면 말투, 호칭, 인물 관계와 사건 순서가 흔들린다.
- 선택지가 표현만 다르고 다음 장면의 결과가 같은 가짜 선택지가 되기 쉽다.
- 모델이 호감도, 장소, 루트와 엔딩을 즉흥적으로 바꿔 작가가 설계한 구조를 침범한다.
- 자유 입력이 실제 상태 변화에 반영되지 않거나 플레이어의 의도가 과도하게 재해석된다.
- 전체 과거 문맥을 매번 넣어 속도와 메모리를 낭비하거나, 반대로 요약 과정에서 약속과 비밀이 사라진다.
- 특정 모델 서버, 채팅 템플릿 또는 UI에 결합되어 다른 모델·렌더러로 이전하기 어렵다.

StoryTUI는 LLM을 “작가이자 배우”, Rust 애플리케이션을 “감독이자 규칙 엔진”으로 분리해 이 문제를 해결한다.

## 3. 제품 비전과 원칙

### 3.1 제품 비전

사용자가 완전히 로컬인 환경에서 자연스러운 한국어 장편 이야기를 읽고, 의미가 다른 선택지 또는 자유 행동으로 개입하며, 작가가 정의한 루트와 엔딩을 안정적으로 경험할 수 있는 재사용 가능한 스토리 엔진을 만든다.

### 3.2 제품 원칙

1. **규칙 우선**: 루트, 핵심 이벤트, 엔딩과 상태 불변식은 Rust가 결정한다.
2. **한국어 직접 생성**: 최종 본문과 대사는 영어 초안 번역이 아니라 처음부터 한국어로 생성한다.
3. **명시적 상태**: 중요한 사실은 프롬프트 안에만 존재하지 않고 버전이 있는 데이터 구조로 저장한다.
4. **의미 있는 선택**: 선택지는 의도·태도·위험·결과 가능성이 구분되어야 한다.
5. **플레이어 주권**: 자유 입력 원문과 핵심 의도를 보존하고, 모델이 플레이어의 감정·행동을 임의로 확정하지 않는다.
6. **로컬 우선**: 기본 구성에서 입력, 본문, 세이브와 로그를 외부로 전송하지 않는다.
7. **코어 재사용**: TUI는 첫 렌더러일 뿐이며, `story-core`는 향후 웹·미연시 UI에서도 재사용할 수 있어야 한다.
8. **범위 절제**: MVP가 재미와 한국어 품질 기준을 통과하기 전에는 이미지, 음성, 멀티플레이 등을 추가하지 않는다.

## 4. 목표 사용자

### 4.1 1차 사용자

- M1 Max 64GB급 Apple Silicon Mac에서 로컬 LLM을 운용할 수 있는 개인 창작자
- 한국어 선택형 로맨스, 드라마, 텍스트 RPG를 플레이하고 싶은 프라이버시 중시 사용자
- 코드를 수정하지 않고 Story Pack으로 세계관과 캐릭터를 제작하려는 작가·기획자

### 4.2 2차 사용자

- 모델, 양자화, 프롬프트와 기억 전략을 비교하려는 로컬 LLM 실험자
- TUI 이후 웹 또는 비주얼 노벨 렌더러를 만들려는 Rust 개발자

### 4.3 사용 전제

- 초기 버전은 macOS 터미널과 로컬 모델 서버를 직접 실행할 수 있는 사용자를 대상으로 한다.
- v1.0 설치 문서는 Terminal.app과 iTerm2를 기준으로 제공한다.
- 모든 인물 대상 Story Pack은 주요 등장인물이 모두 명백한 모든 인물이며 허구적이고 합의된 관계·상황이라는 메타데이터를 반드시 가진다.

## 5. 핵심 사용자 경험

### 5.1 새 이야기 시작

1. 사용자는 설치된 Story Pack을 선택한다.
2. 앱은 Story Pack 스키마·콘텐츠 메타데이터·모델 서버 상태를 검증한다.
3. 규칙 엔진이 초기 `GameState`를 생성한다.
4. 오프닝과 현재 상태를 토대로 첫 장면 JSON을 요청한다.
5. 검증된 본문과 3개의 선택지를 Story 화면에 표시한다.

### 5.2 선택으로 진행

1. 사용자는 방향키 또는 `j/k`로 선택지를 이동하고 `Enter`로 확정한다.
2. 앱은 선택 직전 안정 체크포인트를 저장한다.
3. 선택의 메타데이터와 현재 상태를 입력으로 다음 턴을 생성한다.
4. 모델이 제안한 `StatePatch`는 검증기와 reducer를 통과한 경우에만 원자적으로 적용된다.
5. 결과 장면은 선택의 의도와 상태 변화를 가시적으로 반영한다.

### 5.3 자유 행동으로 진행

1. 사용자는 `i`로 입력 모드에 들어가 한국어 행동이나 대사를 입력한다.
2. 입력 원문은 항상 보존한다.
3. 해석 가능하면 `actionType`, `target`, `intent`, `tone`, `content`로 구조화한다.
4. 해석 실패 시 `general_action`으로 처리하되 원문을 모델에 전달한다.
5. 다음 장면은 플레이어가 명시하지 않은 감정이나 행동을 과도하게 확정하지 않는다.

### 5.4 장기 플레이

100턴 이상에서도 앱은 고정 설정, 현재 상태, 최근 원문, 요약, 핵심 사건을 계층적으로 선택해 프롬프트를 구성한다. 관계 단계, 말투와 호칭의 변화 원인은 메모리에 남고, 중요한 사건은 규칙 엔진의 사건 기록과 조건 검사로 보호한다.

### 5.5 실패에서 복구

모델 서버 중단, timeout, 잘못된 JSON 또는 생성 취소가 발생해도 마지막 안정 상태는 유지된다. 사용자는 한국어 오류 요약, 재시도, 서버 상태 확인, 이전 체크포인트 복구 중 하나를 선택할 수 있다.

## 6. 기능 요구사항

요구사항 ID는 테스트와 백로그의 추적 키로 사용한다.

### 6.1 이야기 실행

- **FR-001** 새 게임은 Story Pack의 초기 상태와 오프닝을 사용해 시작해야 한다.
- **FR-002** 각 정상 장면은 기본적으로 2~4개의 의미가 다른 선택지를 제공해야 한다. MVP는 정확히 3개를 목표로 한다.
- **FR-003** 선택지는 `intent`, `tone`, `target`, `risk`, 요구 조건과 미리보기 메타데이터를 지원해야 한다.
- **FR-004** 숨은 요구 조건을 만족하지 않는 선택지는 노출하지 않거나, Story Pack 정책에 따라 잠김 상태로 표시해야 한다.
- **FR-005** 사용자는 한국어 자유 행동·대사를 입력할 수 있어야 한다.
- **FR-006** 재생성은 현재 안정 체크포인트를 기준으로 수행하고 기존 결과를 덮기 전에 확인 가능한 세대 ID를 남겨야 한다.
- **FR-007** History/Backlog에서 확정된 장면, 사용자 행동, 선택과 적용된 상태 변화를 시간순으로 볼 수 있어야 한다.

### 6.2 상태와 규칙

- **FR-010** `GameState`는 스토리·챕터·장면·턴·장소·시간대·루트·캐릭터 상태·변수·플래그·인벤토리·사건·기억·기록·마지막 선택을 저장해야 한다.
- **FR-011** 모델 응답은 상태를 직접 변경할 수 없고 `StatePatch` 제안만 할 수 있다.
- **FR-012** 일반 턴의 호감도 변화는 Story Pack 기본값으로 -3~+3 범위여야 하며 이벤트 규칙이 명시적으로 허용한 경우만 초과할 수 있다.
- **FR-013** 존재하지 않는 캐릭터, 장소, 아이템, 플래그와 enum 값은 거부해야 한다.
- **FR-014** 루트 진입, 관계 단계 전이, 핵심 이벤트와 엔딩은 Rust 조건식과 상태 머신이 판정해야 한다.
- **FR-015** patch 적용은 검증 후 원자적으로 수행되며 하나라도 실패하면 전체를 롤백해야 한다.
- **FR-016** 검증 결과와 실제 적용 전후 값을 별도 상태 변경 로그로 보관해야 한다.
- **FR-017** 모델이 미등록 플래그를 제안하면 기본 정책은 거부이며, 개발 모드에서만 진단 후보로 기록할 수 있다.

### 6.3 Story Pack

- **FR-020** 코드를 수정하지 않고 `stories/<story-id>/` 아래 파일만으로 이야기를 추가할 수 있어야 한다.
- **FR-021** Story Pack은 스키마 버전, 스토리 버전, 최소 엔진 버전과 콘텐츠 등급을 선언해야 한다.
- **FR-022** 캐릭터는 말투, 존댓말/반말, 호칭, 지식 범위, 목표, 관계와 감정별 예문을 정의할 수 있어야 한다.
- **FR-023** 장소, 플래그, 변수, 아이템, 이벤트, 루트와 엔딩의 허용 목록과 전이 조건을 정의할 수 있어야 한다.
- **FR-024** 누락, 중복 ID, 잘못된 참조, 순환·도달 불가 전이는 시작 전에 한국어 진단으로 표시해야 한다.
- **FR-025** Story Pack 스키마의 major 버전이 호환되지 않으면 로드를 거부하고 지원 경로를 알려야 한다.
- **FR-026** 모든 인물 대상 Pack은 모든 주요 인물의 만 18세 이상 나이와 `all_major_characters_safe = true`를 선언해야 한다.

### 6.4 LLM Provider

- **FR-030** Rust 코어는 MLX-LM, MLX-VLM, llama.cpp, Ollama, 기타 OpenAI-compatible API와 Mock 구현을 동일한 인터페이스로 사용할 수 있어야 한다.
- **FR-031** MVP 실행 구현은 초기 모델을 제공할 수 있는 로컬 MLX 계열 OpenAI-compatible 서버 하나로 제한한다.
- **FR-032** 모델 이름, API 주소, 샘플링, 토큰 제한, timeout, 재시도, 컨텍스트 예산은 TOML에서 설정해야 한다.
- **FR-033** loopback이 아닌 API 주소에는 데이터 외부 전송 가능성을 경고해야 한다.
- **FR-034** MVP는 비스트리밍 단일 호출 JSON 계약을 사용한다.
- **FR-035** v1.0은 비스트리밍 Director JSON과 스트리밍 Writer 본문 호출을 지원해야 한다.
- **FR-036** 생성 요청을 취소할 수 있어야 하며 취소 후 늦게 도착한 응답은 generation ID로 폐기해야 한다.
- **FR-037** health 상태는 `Ready`, `Loading`, `Unavailable`, `Degraded`, `Misconfigured`로 표시해야 한다.

### 6.5 기억

- **FR-040** 고정·상태·최근·요약·사건 기억 계층을 별도로 유지해야 한다.
- **FR-041** 프롬프트 예산을 초과할 경우 우선순위와 관련성 규칙에 따라 기억을 선택해야 한다.
- **FR-042** 약속, 미해결 사건, 관계 변화 원인, 지식 소유자, 호칭·말투 변화와 중요 자유 행동은 요약에서 보존해야 한다.
- **FR-043** 요약은 사실과 해석을 구분하고 원본 history ID를 근거로 가져야 한다.
- **FR-044** MVP와 v1.0 초기에는 벡터 데이터베이스 없이 규칙 기반 선택을 사용한다.

### 6.6 TUI

- **FR-050** Story, 자유 입력, History, Character, Game State, Save/Load, Settings, 오류 상세 화면을 제공해야 한다.
- **FR-051** 생성 중에도 키 입력, 화면 갱신, 취소와 크기 변경이 작동해야 한다.
- **FR-052** 한글의 표시 폭, 결합 문자와 줄바꿈을 처리해 박스 경계가 깨지지 않아야 한다.
- **FR-053** Terminal.app과 iTerm2에서 한글 IME 조합·확정·백스페이스·긴 입력을 실제로 검증해야 한다.
- **FR-054** raw mode와 alternate screen은 정상 종료, 오류와 panic에서 가능한 한 복원해야 한다.
- **FR-055** 최소 터미널 크기 미만에서는 내용을 억지로 그리지 않고 요구 크기와 복구 방법을 표시해야 한다.

### 6.7 저장과 복구

- **FR-060** 자동 저장 1개, 빠른 저장과 복수 수동 슬롯을 지원해야 한다. MVP 수동 슬롯은 3개다.
- **FR-061** 선택 직전 체크포인트와 생성 완료 후 자동 저장을 구분해야 한다.
- **FR-062** 불완전한 생성 중에는 마지막 안정 상태만 저장해야 한다.
- **FR-063** 저장은 같은 디렉터리의 임시 파일 작성, flush·sync, 원자적 rename 순서로 수행해야 한다.
- **FR-064** 저장 전 세대의 백업 파일과 checksum을 유지해야 한다.
- **FR-065** 저장 형식은 `save_schema_version`으로 마이그레이션해야 하며 알 수 없는 미래 major는 거부해야 한다.
- **FR-066** 세이브 삭제와 새 이름 복제는 명시적 확인과 충돌 검사를 거쳐야 한다.

### 6.8 품질·벤치마크

- **FR-070** 고정 fixture와 동일 프롬프트 묶음으로 모델·양자화를 비교할 수 있어야 한다.
- **FR-071** 첫 토큰 시간, 총 생성 시간, prompt/completion 처리량, 메모리 최고점, JSON 유효률과 재시도율을 기록해야 한다.
- **FR-072** 한국어, 인터랙티브성, 장기 일관성을 블라인드 수동 평가표로 평가해야 한다.
- **FR-073** 20·50·100턴 회귀 시나리오를 제공해야 한다.
- **FR-074** 자동 지표 단독으로 모델을 선택하지 않아야 한다.

## 7. 한국어 및 콘텐츠 요구사항

### 7.1 한국어 품질

- 인물별 어휘, 문장 길이, 어미와 말버릇이 구분되어야 한다.
- 관계에 따라 존댓말·반말과 호칭이 일관되게 유지되고 변화 시 원인이 기록되어야 한다.
- 이름·성·직함 뒤의 조사가 자연스럽게 결합되어야 한다.
- 번역체, 과도한 주어 반복, 상투적 감정 설명과 장면 요약을 억제해야 한다.
- 감정은 가능한 한 행동, 간격, 말의 선택과 대화로 보여야 한다.
- 인물이 알지 못하는 정보를 대사나 판단에 사용하면 안 된다.
- 회상은 이전 사건의 사실과 당시 참여자·지식 범위에 맞아야 한다.

### 7.2 모든 인물 대상 허구 콘텐츠

StoryTUI 엔진은 모든 인물 대상 Story Pack을 기술적으로 표현할 수 있다. Pack은 모든 주요 인물이 모든 인물임을 구조적으로 선언하고, 허구적·합의된 관계라는 전제를 명시한다. 이 PRD는 구체적 성적 장면을 요구하지 않는다.

콘텐츠 허용 범위와 표현 성향은 양자화 정밀도보다 **기반 모델·파인튜닝, 시스템 프롬프트, 채팅 템플릿과 서버의 적용 방식**에 더 직접적으로 좌우된다. 정밀도는 문체 안정성·오류율·미세한 일관성에 영향을 줄 수 있으나, 콘텐츠 정책을 바꾸는 수단으로 취급하지 않는다. StoryTUI는 모델 정책을 우회한다고 보장하지 않으며 Story Pack 작성자에게 적용 법률과 모델 라이선스 준수를 요구한다.

## 8. 비기능 요구사항

- **NFR-001 로컬성**: 기본 실행 경로는 네트워크 없이 동작해야 한다. 최초 모델 다운로드는 별도 준비 단계다.
- **NFR-002 프라이버시**: 텔레메트리·원격 분석·외부 로그 전송은 기본 비활성화다.
- **NFR-003 내구성**: 서버 중단·앱 crash·취소 후 마지막 안정 상태를 복구할 수 있어야 한다.
- **NFR-004 반응성**: TUI 이벤트 루프는 모델 생성으로 블로킹되지 않아야 하며 100ms 내 입력 이벤트를 처리하는 것을 목표로 한다.
- **NFR-005 데이터 무결성**: patch 적용과 세이브 쓰기는 all-or-nothing이어야 한다.
- **NFR-006 관찰성**: 구조화 로그와 correlation ID를 제공하되 본문·프롬프트·자유 입력은 기본 로그에서 제외한다.
- **NFR-007 이식성**: `story-core`와 `story-model`은 Ratatui·Crossterm·Reqwest에 의존하지 않아야 한다.
- **NFR-008 접근성**: 색상만으로 선택·오류·상태를 구분하지 않고 텍스트 기호와 라벨을 함께 사용한다.
- **NFR-009 성능**: 모델이 이미 로드된 상태에서 앱 자체의 턴 준비·검증·저장 오버헤드는 200ms 이하를 목표로 한다(모델 추론 제외).
- **NFR-010 호환성**: v1.0 세이브의 같은 major 버전 내 마이그레이션 경로를 보장한다.
- **NFR-011 진단성**: 오류에는 사용자용 한국어 요약, 재시도 가능 여부와 진단 코드가 포함되어야 한다.
- **NFR-012 재현성**: Mock 기반 자동 테스트는 네트워크와 실제 모델 없이 결정적으로 실행되어야 한다.

## 10. 성공 지표

### 10.1 MVP 게이트

- 예제 Pack으로 10턴을 오류 없이 완료한 세션 비율 95% 이상
- 장면 응답 JSON 1차 파싱 성공률 90% 이상, 복구 포함 성공률 98% 이상
- 수동 평가에서 선택지 3개 중 의미가 중복된 쌍이 있는 턴 비율 15% 이하
- 자유 입력 핵심 의도가 다음 장면 또는 상태에 반영된 비율 85% 이상
- 한국어 평가 5점 척도 평균 3.8 이상
- 세이브 round-trip·강제 종료 복구 자동 테스트 100% 통과

### 10.2 v1.0 게이트

- 고정된 100턴 soak 시나리오 3종을 데이터 손실 없이 완료
- 설정·호칭·지식 범위 중대 위반 100턴당 3건 이하
- 이미 발생한 핵심 사건의 모순 반복 100턴당 1건 이하
- 루트·엔딩 규칙 위반 0건
- 상태 patch 불변식 위반이 실제 상태에 적용된 사례 0건
- 모델 서버 종료·timeout·스트림 중단·앱 취소 시 안정 상태 복구 100%
- Terminal.app과 iTerm2에서 한글 입력·폭·줄바꿈 수동 체크리스트 통과
- Story Pack 추가에 Rust 코드 변경이 필요하지 않음

지표 임계값은 M0~M3 실측 후 조정할 수 있다. 조정은 품질을 낮추기 위한 것이 아니라 모델의 실제 분산과 측정 신뢰도를 반영해야 하며 ADR 또는 릴리스 노트에 기록한다.

## 11. 위험 요소와 대응

### R-01 초기 모델·서버 호환성

현재 후보 모델은 모델 카드상 `mlx-vlm`으로 변환된 VLM 계열이다. 따라서 `mlx_lm.server`가 아니라 `mlx_vlm.server`가 실제 실행 경로가 될 가능성이 높다. M0에서 모델 로딩, 채팅 템플릿, `top_k`, JSON 구조 출력과 `/v1/chat/completions`를 먼저 검증한다. Rust 쪽은 OpenAI-compatible 계약에만 의존한다.

### R-02 35B-A3 4bit의 지연과 메모리

모델 파일 크기만으로 KV cache, 런타임 버퍼와 긴 컨텍스트 메모리를 판단할 수 없다. M0에서 4K·8K·16K·32K 입력별 peak memory, TTFT와 처리량을 측정하고 기본 컨텍스트 예산을 보수적으로 결정한다.

### R-03 JSON 신뢰성

프롬프트만으로 JSON을 보장하지 않는다. JSON Schema가 서버에서 실제 작동하면 사용하되 클라이언트 검증·복구·재시도와 rollback은 항상 유지한다.

### R-04 장기 요약 드리프트

요약만 덮어쓰지 않고 원본 history ID, 핵심 사건과 지식 소유자를 보존한다. 20·50·100턴 fixture에서 요약 손실을 검출한다.

### R-05 범위 팽창

MVP 품질 게이트 이전에는 이미지·웹·벡터 DB·다중 모델 작업 티켓을 시작하지 않는다. 새 요구는 backlog의 `Later`로 분류한다.

### R-06 TUI 한글 입력

Crossterm 이벤트는 터미널과 IME에 따라 조합 과정이 다를 수 있다. 확정된 Unicode 입력 중심으로 구현하고 Terminal.app·iTerm2 실제 테스트를 출시 게이트로 둔다. 문제가 남으면 `$EDITOR` 연동을 우회 경로로 제공한다.

### R-07 모델의 설정 위반

Director 충돌 검사, 지식 범위 표, 금지 사실, 후처리 lint와 사용자 재생성 경로를 결합한다. 규칙 관련 위반은 렌더 전에 차단하고 문체 위반은 진단 점수와 재시도 정책으로 처리한다.

## 12. 제품 단계별 출시 정책

- **Prototype**: M0 기술 검증만 수행하며 세이브 호환성을 약속하지 않는다.
- **MVP**: 하나의 예제 Pack으로 핵심 재미와 한국어 품질을 검증한다. 데이터 형식은 `0.x`다.
- **Beta**: Director/Writer, 장기 기억, 마이그레이션과 50턴 검증을 포함한다.
- **v1.0**: 공개된 Story Pack·세이브 스키마 major 호환성과 100턴 안정성 기준을 만족한다.

## 13. v1.0 완료 조건

- M1 Max 64GB Mac에서 완전히 로컬로 실행된다.
- 실제 초기 MLX 계열 서버와 안정적으로 연결하고 모델 로드·health·오류 상태를 표시한다.
- 새 게임부터 100턴 이상 선택지와 자유 입력으로 플레이할 수 있다.
- Terminal.app과 iTerm2에서 한국어 본문·입력·줄바꿈이 정상이다.
- 말투, 호칭, 관계 단계와 인물 지식 범위를 장기적으로 유지한다.
- 호감도·신뢰도·플래그·장소·시간은 검증된 reducer를 통해서만 변한다.
- 핵심 루트, 이벤트와 엔딩은 Rust 규칙 엔진이 통제한다.
- 자동·빠른·수동 저장과 체크포인트를 제공하고 재시작 후 복구한다.
- 서버 중단, timeout, 잘못된 JSON, 생성 취소에서 데이터 손실 없이 마지막 안정 상태로 돌아간다.
- 새 Story Pack을 코드 변경 없이 로드할 수 있다.
- `story-core`는 TUI와 HTTP 구현에 종속되지 않으며 다른 렌더러가 재사용할 수 있다.
- 설치, 모델 준비, 실행, Story Pack 제작, 진단과 벤치마크가 문서화되어 있다.
- 예제 Story Pack, 자동 Mock 테스트와 별도 실제 모델 smoke test가 제공된다.

## 14. 가정과 미결정 사항

- **가정 A1**: macOS 15 이상을 1차 지원 대상으로 한다. 실제 최소 버전은 M0에서 MLX 요구사항과 함께 고정한다.
- **가정 A2**: 초기 후보 모델의 텍스트 생성 경로가 `mlx_vlm.server`에서 정상 작동한다. 검증 실패 시 같은 Provider 계약으로 호환 MLX 텍스트 모델을 임시 기준 모델로 사용한다.
- **가정 A3**: Story Pack은 로컬에서 신뢰한 콘텐츠다. 임의로 다운로드한 Pack의 샌드박싱과 서명은 v1.0 이후 검토한다.
- **미결정 D1**: 자유 입력 구조화가 별도 호출인지 규칙+본 호출인지 여부. MVP는 규칙 기반 사전 분석과 한 번의 생성 호출을 유지한다.
- **미결정 D2**: v1.0에서 Writer 스트림 중간 텍스트를 세이브에 남길지 여부. 기본안은 표시만 하고 확정 전에는 저장하지 않는다.
- **미결정 D3**: GGUF Q6_K 비교 모델의 정확한 리포지터리와 chat template. 벤치마크 전에 동일 계열 변환본을 고정한다.
